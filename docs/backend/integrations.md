# Внешние интеграции

В прототипе все интеграции имитированы (`setTimeout` + «в прототипе имитировано»). Ниже — что нужно от каждой системы по поведению интерфейса. Названия скоупов и методов API площадок — **предложение, сверить с актуальной документацией площадки**: они меняются, а в прототипе их нет.

Общие правила:
- Подключения соцсетей и карт принадлежат **клиенту** (`CONN[клиент][площадка]`), CRM — **кабинету** (финансы агентства). Новый кабинет — без подключений.
- Чужие интерфейсы не рисуем: свои промежуточные экраны «Откроется VK… пароль мы не видим и не храним» → OAuth → возврат в то же окно (`after`).
- Токены — только на сервере, зашифрованы; фронт видит `status`, `name`, `url`, `connected_at`, `expires_at`.
- Истечение доступа: `exp` → `connAuto()` = false → публикации «Не вышел», ответы во входящих — «Скопировать ответ» + «Переподключить». Фоновая проверка токенов (см. notifications-and-jobs.md).
- Ограниченные в РФ площадки — в конце списков с подписью «огр. в РФ» (`PL_RU = ig, li, yt`) и честным предупреждением (`PLAT_NOTE`).

## 1. Соцсети клиента — публикация, комментарии, статистика

| Площадка | Режим | Подключение | Пишем | Читаем | Особенности |
|---|---|---|---|---|---|
| **VK** | `auto` | OAuth администратора сообщества → выбор сообщества (`connOauth`) | посты (текст + фото, альбом для карусели до 10), сторис, клипы | комментарии, сообщения сообщества, статистика записей (охват, реакции, сохранения) | основная площадка; лимит текста 16 384, в ленте видно ~300 знаков; 3–5 хэштегов. Токен сообщества с правами на стену, фото, видео, сообщения, статистику; Callback API для комментариев — **уточнить** |
| **Telegram** | `auto` | пользователь добавляет **@MakerPostBot** админом канала с правом «Публиковать сообщения» и даёт ссылку `t.me/…`; проверяем, что бот админ (`connTg`) | сообщения, фото с подписью (лимит подписи 1 024), альбом до 10 | просмотры постов; комментарии — только если к каналу привязана группа обсуждений, бот в ней | личные сообщения «в канал» бот читать не может — в демо есть `dm` из Telegram, источник не определён (open-questions) |
| **TenChat** | `remind` | «Включить напоминания» — публиковать сервисам не даёт | — | — | в назначенное время шлём маркетологу готовый текст и картинку |
| **Instagram** | `auto`, огр. в РФ | OAuth бизнес-аккаунта (через Meta) | пост 4:5, карусель до 20, сторис, Reels | комментарии, статистика | Meta признана в РФ экстремистской: контент готовим, **рекламу размещать нельзя**; юр-оценку хранения токенов — open-questions |
| **LinkedIn** | `auto`, огр. в РФ | OAuth страницы компании | пост 1.91:1, карусель как PDF-документ | — | заблокирован в РФ с 2016; версия для зарубежной аудитории |
| **YouTube** | `auto`, огр. в РФ | OAuth канала | Shorts (клипы) | — | работает с ограничениями скорости |

Форматы и безопасные зоны — `SOC_FMT` (пропорции, размеры, `top/bot` в % для сторис и клипов, вид ссылки: «Ссылка» / «Кнопка-ссылка»).

**Нужно от интеграции:**
- `publish(connection, publication_version, media[]) → {external_id, url}` идемпотентно по `publication_id + platform`.
- Ошибки: `token_expired` → `CONN.exp`, публикация `fail{pl, why}`; `rate_limited` → повтор с backoff; `rejected` → `fail` с текстом площадки.
- Режим `remind`: не вызываем площадку, создаём напоминание маркетологу (Главная + почта/Telegram по настройкам) с текстом и картинкой.
- Статистика публикаций (`SST`): охват, реакции, комментарии, сохранения по каждому посту, регулярный сбор.
- Входящие (`INBOX`): комментарии к постам, личные сообщения, отзывы в сообществе; ответ от имени сообщества; «Скрыть» спам — скрыть/удалить комментарий в площадке.

## 2. Карты: 2ГИС и Яндекс Карты (Яндекс Бизнес)

- Подключение на странице клиента, блок «Соцсети и карты клиента»: «Войдите как владелец карточки и разрешите Maker читать отзывы и отвечать на них».
- Читаем: отзывы (автор, текст, звёзды 1–5, дата), рейтинг карточки и число отзывов (`RATING`).
- Пишем: ответ владельца на отзыв (виден всем, кто открывает карточку).
- **Риск:** публичных API для ответов на отзывы у обеих площадок может не быть или они партнёрские — уточнить; альтернатива — режим «скопировать ответ» как для неподключённых площадок. → open-questions.

## 3. CRM агентства — финансы (только чтение)

| CRM | Подключение | Что читаем |
|---|---|---|
| amoCRM | OAuth 2.0 интеграции, аккаунт `*.amocrm.ru` | воронки и этапы, сделки (название, бюджет, этап, кастомные поля суммы/даты), счета и оплаты |
| Битрикс24 | OAuth приложения или входящий вебхук, портал `*.bitrix24.ru` | направления сделок, стадии, сделки, счета |
| Мегаплан | API аккаунта | сделки и счета |
| Таблица | загрузка XLSX/CSV по шаблону: клиент, сумма в месяц, дата оплаты, статус | строки |

- После доступа — сопоставление (`finMap`): воронка с клиентами агентства, этап «оплачено», поле суммы, поле даты. Клиенты Maker сопоставляются по названию сделки.
- Ничего в CRM не меняем. «Обновить» — ручная синхронизация; плюс по расписанию.
- Подключить можно несколько; источник — первая подключённая (`FIN.src`) — правило слияния не определено (open-questions).
- «Напомнить» о просрочке — письмо клиенту агентства со счётом во вложении (имитация): кто отправитель и откуда счёт — open-questions.

**Отдельно — сверка оплат для «Результатов рекламы»** (`crmOpen/crmRun`): сейчас загрузка выгрузки оплат CSV/XLSX (дата, телефон или email, сумма) → сопоставление с заявками по телефону и UTM → спорные решает пользователь. Это CRM **клиента**, не агентства; автоматизация — open-questions.

## 4. Реклама: VK Реклама, Яндекс Директ, ОРД

**Сейчас в прототипе рекламные кабинеты не подключены.** Кампания запускается «в ручном режиме», расход/клики/заявки вносятся руками каждый день (`openEntry/enSave`, подсказка «где взять цифры»: VK Реклама → «Статистика»; Директ → «Мастер отчётов»), пауза в площадке — вручную, UTM-ссылки генерирует Maker (`utmLinks`: `utm_source=vk|yandex`, `utm_medium=cpc`, `utm_campaign=<id>-<hash>`, `utm_content=banner-vN|video`). Модерация баннеров — имитация («обычно до суток»).

Если подключать (предложение):
- **VK Реклама:** OAuth агентства/рекламодателя; создание объявлений из комплекта баннеров (формат «Лента», «Истории», «Клип-обложка», «Карусель»), статус модерации и причина отклонения (`BN_ST.bad`, `why`), статистика по дням → `CampaignDay`.
- **Яндекс Директ:** OAuth, API кампаний и объявлений (форматы 600×600, 960×640, 300×250, 240×400, 728×90, 320×480), Reports API → расход, клики, конверсии.
- **ОРД и erid** (38-ФЗ): в каждом баннере «Реклама · рекламодатель · erid»; сейчас erid вставляют руками («вставьте токен из ОРД»), без него отправка блокируется. Интеграция с ОРД (регистрация креатива → получение erid, ежемесячная отчётность по актам) — open-questions. Рекламодатель — `ADV[клиент]` (юрлицо/ИП клиента).
- Сигналы, которые уже есть на ручных данных и должны работать на авто: не внесены данные; цена заявки выросла >20% за 3 дня; бюджет кончится раньше срока; заявка в другом канале дешевле.

## 5. Сайты клиента, аналитика, коллтрекинг

- Публикация лендингов: свой домен клиента (проверка DNS, «ждём DNS, до 24 ч»), HTTPS, или временный `*.maker.site` (`SITES`). Подключение домена — заглушка.
- **Яндекс Метрика** — в источниках «Результатов» показана как подключённая; что именно берём (визиты, цели) — не описано. Предложение: счётчик на страницах Maker + цели формы заявки.
- **Коллтрекинг** — «не видим — коллтрекинг не подключён»; порядок подключения из прототипа: Calltouch, дальше Roistat, Comagic, Callibri. Нужно: звонки как заявки с атрибуцией по UTM.
- Снятие стиля с сайта (`stRescan`, новый клиент со ссылкой), поиск аудиторий на сайте (`grSuggestSite`), чтение каналов-источников голоса (`voSrc`) — парсинг публичных страниц; уважать robots, таймауты, только публичный контент.

## 6. Вход, уведомления, оплата

- **Яндекс ID** — вход и привязка в профиле: идентификатор, почта, имя, аватар. Свои экраны «Открываем Яндекс ID».
- **Коды входа:** письмо и SMS с 4-значным кодом; повтор через 45 с; провайдер SMS — open-questions.
- **Уведомления пользователю:** почта и Telegram-бот (подключение бота в профиле). Тот же ли это бот, что @MakerPostBot, — open-questions.
- **Оплата Maker:**
  - картой — переход на страницу банка/эквайера → вебхук об оплате → пополнение (`topup`); привязка карты для автопополнения (на 1 000 ₽ при остатке < порога) — токен карты у эквайера;
  - счёт для юрлица — PDF счёта на почту, зачисление 1–2 рабочих дня (банковская выписка или ручное подтверждение);
  - закрывающие документы: квитанция, акт (подписан электронно), УПД, счёт — PDF (`data-engine="billing-doc"`); ЭДО-оператор — open-questions;
  - удаление аккаунта: «деньги с баланса вернём» — процедура возврата — open-questions.

## 7. Генерация

В интерфейсе моделей нет (не агрегатор): у кадров — «Что снимаем» и «Качество», у видео — «Как снимаем» (быстрее и дешевле / реалистичнее / плавнее). Внутренние метки в данных:

| Тип | Внутренние модели в прототипе | Цена для пользователя |
|---|---|---|
| Кадры | Seedream, Flux (`SERIES.model`) | 1,47–7,36 ₽ за кадр |
| Видео | Kling turbo / Kling pro / Veo (`VD_MODE`) | 12,40–41,03 ₽ |
| Тексты, разбор, чат | не названы | 0,31–2,63 ₽ |
| Распознавание голоса | в прототипе — Web Speech API браузера, без него подставляется пример | — |

Требования:
- Абстракция провайдера: `generate_image(prompt, style, format, quality)`, `generate_video(first_frame, motion, duration, formats, mode)`, `llm(task, context, schema)`, `stt(audio)`.
- Стиль клиента в каждом запросе к изображениям: манера фото (свет, цвет, композиция, «избегать»), эталоны, палитра. Картинки генерятся **без текста** — подписи и баннеры собирает код (canvas/HTML) в шрифтах клиента.
- **Автоприёмка** кадров: отсев брака (искажённые пальцы, лица, лишний текст) → «Не получился» с причиной, пересъёмка бесплатно.
- Видео — асинхронно с прогрессом; файлы MP4 по каждому формату; клип — субтитры SRT и обложка.
- Доступность провайдеров из РФ, оплата, передача данных за рубеж (152-ФЗ) — open-questions.
