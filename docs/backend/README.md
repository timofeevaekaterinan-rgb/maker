# Maker — документация для бэкенда

## Что за продукт

- Maker — кабинет маркетолога или агентства. Внутри кабинета — **клиенты**, которых он ведёт.
- Для каждого клиента сервис генерирует контент в его стиле и голосе: кадры, ролики, посты, карусели, сторис, клипы, баннеры, лендинги, презентации.
- Цепочка работы: рассказ о клиенте → стратегия → контент-план → публикации → результаты.
- Рядом: рекламные кампании (сейчас данные вносят руками), входящие из соцсетей и отзывы с карт, финансы агентства из CRM.
- Всё делается через чат с агентами-персонажами (Мика, Тим, Ася, Лев, Нора). Чат заполняет поля создания и запускает генерацию.
- Клиент маркетолога согласует материалы по ссылке, без регистрации.
- Оплата — с баланса за каждое действие, без подписки. Цена — «до N ₽», дорогие действия подтверждаются.
- Чего не знаем — не выдумываем: в тексте ставим плашку-пропуск `[…]` и спрашиваем.

Источник правды — `maker/prototype.html` (один файл, данные в JS-массивах, генерация и интеграции имитированы). Правила UI и решения по экранам — `maker/CLAUDE.md`. Архивные `prototype-v1…v5.html` и `landing.html` не описываем.

## Как искать в прототипе

Файл ~1,3 МБ, ~11 400 строк. Читать целиком не нужно — ищите по имени:

```bash
grep -n "^var SOC=" maker/prototype.html        # данные
grep -n "function socSchedule" maker/prototype.html  # действие
grep -n 'id="v-plan"' maker/prototype.html      # разметка экрана
grep -n 'data-engine' maker/prototype.html      # кнопки, где файл отдаёт только движок
```

Многие функции в конце файла переопределяются обёртками (`var o=fn;fn=function(){…}`) — смотрите все вхождения имени, не только первое. Ссылки в документах — вида `prototype.html: socSchedule()`. Демо-дата «сегодня» — `TODAY = 14 окт 2026`.

## Глоссарий

| Термин | Значение | В коде |
|---|---|---|
| Кабинет | Аккаунт маркетолога или агентства. Владеет клиентами, балансом, командой | `CAB`, `PF` |
| Клиент | Компания, которую ведёт маркетолог. Всё содержимое привязано к клиенту. Слово «проект» в UI не используем | `PROJECTS`, поле `p` у всех сущностей |
| Текущий клиент | Один на весь кабинет, выбирается в сайдбаре; «Все клиенты» — без фильтра | `CLIENT`, `clientSet()` |
| Клиент по ссылке | Заказчик маркетолога. Открывает ссылку без входа, согласует материалы и отвечает на бриф | `cvOpen()`, экран `#cv` |
| Стиль | Визуальный код клиента: цвета по ролям, шрифты, скругление, манера фото, логотип, версии | `DESIGN[клиент]` |
| Голос | Тон (2 ползунка), «так говорим / так не говорим», источники голоса | `DESIGN[клиент].tone`, `.say`, `VOICE` |
| База фактов | Что знаем о клиенте наверняка, по категориям. Генерация берёт факты только отсюда | `FACTS` |
| Аудитории | Группы людей, которым адресуем материалы. Не «персоны» с выдуманными именами | `GROUPS` |
| Плашка, пропуск `[…]` | Неизвестное в тексте: `[ваша скидка]`. Не выдумываем. Ответ один раз → подставляется во все материалы клиента и сохраняется фактом | `faGaps()`, `faFill()`, `PH()` |
| «уточняем» | Так клиент по ссылке видит пропуск | `cvClean()` |
| «Чего не хватает» | Все пропуски клиента с количеством и местами | `faGaps()` |
| Уточняющие вопросы | Вместо ответа с пропусками чат спрашивает по одному с вариантами | `CHQ`, `chqCard()` |
| Рассказ о клиенте | Свободный текст, который Maker раскладывает на аудитории, факты, голос, стратегию | `ikParse()` → `ikApply()` → `ikShow()` |
| Стратегия | Одна на клиента: цель, KPI, позиционирование, мысли, площадки, рубрики с долями | `STRATS[клиент]` |
| Контент-план, тема | Темы на даты, собираются только из стратегии. Тема = «материал» | `PLAN` |
| Публикация | Пост, карусель, сторис или клип. Одна модель, версии под площадки | `SOC`, `SOC_FMT` |
| Площадка | VK, Telegram, TenChat, Instagram, LinkedIn, YouTube; для отзывов — 2ГИС, Яндекс Карты | `PLAT`, `CONN_PL` |
| Подключение | Доступ к соцсети или карточке **клиента** (не кабинета). Режимы: `auto` — публикуем сами, `remind` — напоминание с готовым текстом | `CONN[клиент][площадка]` |
| Кадр, серия | Сгенерированное или загруженное фото, серия — группа кадров | `SHOTS`, `SERIES` |
| Комплект баннеров | 1–3 варианта текста × 10 форматов, маркировка рекламы, erid | `BSETS`, `FMTS` |
| Колода | Презентация: сначала план (outline), потом сборка слайдов | `DECKS` |
| Кампания | Цель, срок, бюджет, аудитории, состав (страница, баннеры, ролик). Цифры по дням | `CAMPS`, `DAYS` |
| Журнал | Все списания и пополнения баланса Maker | `JOURNAL`, `charge()` |
| Платное действие | Проходит через ворота: не хватает денег → пополнить; дороже порога → подтвердить | `spendGate()`, `LIMITS` |
| Статусы | Одна шкала слов: Черновик → Ждёт проверки (вы) → На согласовании (клиент) → Согласован/Принят → На модерации (площадка) → Запланирован → Опубликован/Работает. Отказы: Не получился, Отклонён площадкой, Не вышел | см. data-model.md |
| Агенты-персонажи | Мика — координатор, Тим — стратег, Ася — контент-редактор, Лев — реклама, Нора — бренд. Рисованные аватары, можно выключить | `AG`, `DK_AG_V` |
| Колонка чата (док) | Чат между меню и экраном, работает на любом экране, знает, где вы | `DOCK`, `dockSend()` |
| Сценарий создания | Создание через чат: текст → карточка «Сделаю так:» с полями → запуск | `DCR`, `dcrStart()` |
| Стартовый набор | Для новых пользователей: бриф → разбор → стратегия, план, посты, баннеры, лендинг, колода разом. В коде `pk*`, экран `pack` | `PK`, `pkStart()` |
| Напоминания | Что сделать вам (Главная). Не путать с уведомлениями | `renderToday()`, `todayExtra()` |
| Уведомления | Что случилось без вас (колокольчик) | `NTF`, `ntfPush()` |
| Сценарии данных | Демо-состояния кабинета: новый, первые шаги, активный, деньги кончились | `STATE` |
| Системные состояния | Загрузка, ошибка, нет сети | `SYSST` |
| erid, ОРД | Токен маркировки рекламы, выдаёт оператор рекламных данных. Без erid баннер не отправить | `bnSend()` |
| Период | Только длительностью: 1 · 3 · 6 · 12 месяцев, без дат | `perRange()`, `PER_N` |

Пометки в документах: **(предложение)** — додумано, в прототипе этого нет; **(имитация)** — в прототипе есть только видимость; вопросы — в open-questions.md.
