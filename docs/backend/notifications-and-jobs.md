# Уведомления, напоминания и фоновые задачи

Два разных механизма (`CLAUDE.md`, «Уведомления и напоминания — разные вещи»):
- **Уведомления** — что случилось без вас. Колокольчик на любой странице, плюс почта/Telegram по настройкам.
- **Напоминания** — что сделать вам. Только Главная, блок «Напоминания» (3 + «Ещё N»), у каждого «Сделать/Открыть» и «⋯ Отложить до завтра / Уже сделано».

Ответ клиента по ссылке и готовый клип пишут уведомление сразу; правки клиента — ещё и напоминанием.

## 1. Уведомления (колокольчик, `NTF`, `ntfPush`)

Поля: `p` клиент (пусто — общее), `k` вид-иконка, `t` заголовок, `s` подпись, `at`, `read`, цель перехода. Лента свежими сверху, непрочитанные — с точкой, счётчик (9+), «Прочитать все», шестерёнка → настройки. При выбранном клиенте — его и общие.

| Событие | `k` | Кто создаёт | Переход | Канал настройки `PF.ntf` |
|---|---|---|---|---|
| Клиент согласовал стратегию / тему / публикацию / страницу | `ok` | `cvOk` → `cvNtf` | в материал | `appr` |
| Клиент просит правки (с текстом) | `fix` | `cvFixGo` → `cvNtf` | в материал | `appr` |
| Клиент ответил на вопросы брифа | `ok` | `cvBriefGo` | База фактов | `appr` |
| Клип готов / ролик готов | `ready` | `socRender`; `vdTick` (сейчас тост) | в клип/ролик | `render` |
| Стартовый набор готов | `ready` | `pkFinish` | экран набора | `render` |
| Площадка отклонила баннеры (причина) | `bad` | модерация (демо `ntfSeed`) | комплект | — **(предложение: `appr` или новый `moder`)** |
| Баннеры прошли модерацию | `info` | модерация (демо) | комплект | то же |
| Публикация не вышла | `bad` | планировщик публикаций (в прототипе — только напоминание) | пост | **(предложение)** |
| Баланс ниже порога / 0 ₽ | `money` | после `charge()` (сейчас тост) / демо | Оплата | `bal` |
| Коллега принял приглашение | `team` | принятие инвайта (демо) | Команда | — |
| Сводка за неделю по клиентам | — | еженедельно | — | `week` (только почта/Telegram) |
| Новости Maker | — | вручную | — | `news` |

Требования: дедупликация (одно событие — одно уведомление), доставка в SSE (`notification.new`) и по каналам из настроек, тихие часы для внешних каналов. Пустой колокольчик — «Пока тихо».

## 2. Напоминания на Главной (`renderToday` + `todayExtra`)

Порядок: сначала то, что `todayExtra` добавляет в начало, и правки клиента (`unshift`), затем остальные. Фильтр по текущему клиенту; скрытые (`TD_HIDE`) убираются. **(предложение)** Сервер вычисляет список по данным и хранит только отметки «отложено до» / «сделано» по стабильному ключу (`type:id`), а не по тексту, как в прототипе.

| # | Условие | Текст (пример) | Кнопка |
|---|---|---|---|
| 1 | публикация `fail` | Пост «…» не вышел в VK — доступ истёк | Переподключить |
| 2 | есть новые входящие (не спам) | 3 сообщения из соцсетей без ответа | Ответить |
| 3 | автоотчёт собран и ждёт проверки (`auto && rev`) | Отчёт «Итоги сентября» для «Вита» собран — проверьте и отправьте | Проверить |
| 4 | правки клиента: стратегия / тема / публикация / страница (`fb && draft`) | Клиент просит правки: пост «…» · «текст» | Открыть |
| 5 | баланс < 1 ₽ | На балансе 0 ₽ — генерация на паузе | Пополнить |
| 6 | N дней без постов у клиента (`SOC_LAST`, демо) | «Вита»: 4 дня без постов | Сделать (задача в чат) |
| 7 | стратегия `check` | Стратегия «…» ждёт согласования клиента | Открыть |
| 8 | стратегия `ok`, нет плана на следующий месяц (в коде захардкожен ноябрь) | Контент-план «…» на следующий месяц ещё не составлен | Сделать |
| 9 | темы `check` | 2 темы «…» ждут согласования клиента | Открыть |
| 10 | сигналы кампаний (`campSignals`) | не внесены расход и заявки за 12–13 окт; цена заявки выросла на N% за 3 дня; бюджет закончится ~дата | Внести / Открыть |
| 11 | страница `check` | Проверьте страницу «…» | Проверить |
| 12 | кадр `bad` | «…» не получился — переснимем бесплатно | Открыть |
| 13 | публикация `check` | Пост «…» ждёт согласования клиента | Открыть |
| 14 | клиент согласовал публикацию (`cl==='ok' && st==='ok'`) | Клиент согласовал: пост «…» — можно планировать | Запланировать |
| 15 | колода `check` | Проверьте план презентации «…» | Проверить |

Новый кабинет вместо списка — «Первые шаги N из 4» (`renderOnboard`): клиент → стратегия → контент-план → первый пост; текущий шаг — «Сделать», пройденные — «Готово», будущие — «Потом».

Те же сигналы попадают в «Нужно от вас» на странице клиента и в «Что стоит сделать» в «Результатах» — **одна функция сигналов** (правило «Цифры и деньги»), не дублировать расчёт.

## 3. Фоновые задачи

| Задача | Когда | Что делает | Результат / ошибки | Прототип |
|---|---|---|---|---|
| **Публикация по расписанию** | в `date+time` публикации, по таймзоне пользователя | для `auto`-площадок — публикация; для `remind` и неподключённых — напоминание с текстом и картинкой | все успешны → `pub`; ошибка доступа → `fail{pl,why}`, `CONN.exp`, уведомление + напоминание; временная ошибка → повтор с backoff; частичный успех по площадкам — open-questions | `socScheduleGo`, `socSplit`, `socRetry` |
| **Проверка токенов подключений** | ежедневно + при ошибке API | помечает `exp`, заранее предупреждает **(предложение)** | напоминание «Переподключить» | `CONN.exp`, `connLine` |
| **Автоотчёт за месяц** | 1-го числа, для клиентов с `autoReport` | колода за прошлый месяц из кампаний, публикаций, плана | `DECKS{auto, rev}`, списание 2,63 ₽ (недостаточно денег → не собирать, напоминание) | `repBuild`, `AUTO_REP` |
| **Сбор входящих и отзывов** | вебхуки VK/Telegram + опрос карт (раз в N минут) | новые комментарии, сообщения, отзывы; разметка `tag`/`ask`; черновик ответа по запросу | `INBOX.new`, счётчик «Входящих», напоминание | `INBOX`, `ibDraft` |
| **Рейтинг карточек** | ежедневно | оценка и число отзывов | `RATING` | — |
| **Статистика публикаций** | ежедневно для постов за 120 дней | охват, реакции, комментарии, сохранения | `SST` → «Публикации и ЦА», отчёты, подсказка «Дать больше тем» | `SST` |
| **Обновление финансов из CRM** | по расписанию (раз в час/сутки) + «Обновить» | оплаты, счета, сроки по сопоставлению | `FIN.cl`, `FIN.src.d` «обновлено …»; ошибка доступа → «Переподключить CRM» | `finSync` |
| **Сверка оплат с заявками** | сейчас вручную по файлу; **(предложение)** раз в неделю из CRM клиента | продажи и выручка по дням, спорные | `DAYS.sl/rev`, `CRM.until`; >7 дней без сверки → сигнал «Сверить с CRM» | `crmRun`, `resultInsights` |
| **Контроль ручного ввода кампаний** | ежедневно утром | дни идущих кампаний без цифр → `miss[]` | сигнал «не внесены расход и заявки» | `campSignals` |
| **Статистика рекламы** (если подключить кабинеты) | ежедневно | `CampaignDay` из VK Рекламы / Директа | заменяет ручной ввод | — |
| **Модерация баннеров** | вебхук/опрос площадки | `proc → pub | bad(why)` | уведомление `info`/`bad` | `bnSend`, `BN_ST` |
| **Окончание кампаний** | ежедневно | `to < сегодня` → `done` **(предложение)** | — | `CM_ST.done` |
| **Рендер ролика и клипа** | очередь генерации | прогресс в SSE, по готовности `check` | уведомление `ready`; ошибка → возврат холда | `vdTick`, `socRender` |
| **Генерации (все)** | очередь | см. api.md §4 | холд → списание / возврат | `openBuildModal` |
| **Стартовый набор** | очередь, шаги последовательно | разбор → стратегия → план → посты → … | списание по шагам; сбой шага — «не получилось — попробуйте ещё раз», цепочка продолжается | `pkStep` |
| **Порог баланса и автопополнение** | после каждого списания | `< lowAt` → уведомление; `auto` → платёж картой | `JOURNAL topup` | `charge`, `LIMITS` |
| **Сводка за неделю** | раз в неделю | по клиентам: что вышло, что ждёт | почта/Telegram | `PF_NTF.week` |
| **Проверка DNS/HTTPS доменов** | раз в N минут до 24 ч | статус `wait → ok` | `SITES.ck` | `SITES` |
| **Удаление** | через 14 дней после запроса аккаунта; через срок undo для объектов | физическое удаление | — | `pfDelete`, `delRun` |
| **Экспорт «Мои данные»** | по запросу | архив | ссылка на скачивание | `dlMyData` |
| **Просмотры колод по ссылке** | события от публичной страницы | когда открыли, сколько смотрели каждый слайд | `DECKS.share` | `dkShare` |

Общие требования к очереди: идемпотентность по ключу (публикация + площадка + время; отчёт клиент + месяц), повторы с backoff, видимость статуса в UI через SSE, никаких двойных списаний.
