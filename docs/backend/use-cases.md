# Пользовательские сценарии

Акторы: **М** — маркетолог (участник кабинета), **К** — клиент по ссылке (без входа), **С** — система (расписание, вебхуки). Эндпоинты — из [api.md](api.md) (предложение). «Прототип:» — функции в `prototype.html`.

Сквозные правила, которые применяются во всех сценариях ниже и не повторяются:
- Любое платное действие идёт через ворота денег (UC-42): 402 / 409 подтверждение / холд → списание в журнал.
- Генерация берёт факты только из базы фактов клиента; неизвестное — плашка `[…]`, не выдумка.
- Всё создаётся **черновиком**. Из чата ничего не публикуется.
- Отправка клиенту с пропусками — окно «Осталось пропусков: N» → «Заполнить» / «Отправить как есть» (`sendCheck()`); клиент видит «уточняем».
- Действие над чужим клиентом (уведомление, ссылка) переключает текущего клиента (`clientFollow()`).

## A. Вход и кабинет

### UC-01 Вход по коду
- **Актор:** М. **Триггер:** экран входа, «Получить код»; или `prototype.html?login` с лендинга.
- **Шаги:** ввод почты или телефона в одно поле (тип определяем сами, маска `+7 (___) ___-__-__`) → код из 4 цифр → автопроверка при вводе/вставке → существующий: в свой кабинет; новый: UC-04.
- **API:** `POST /auth/code`, `POST /auth/code/verify`.
- **Ошибки:** опечатка в почте; не 10 цифр телефона; неверный код — «осталось N попытки»; 3 ошибки → блок 10 мин (`423`); «Отправить ещё раз» через 45 с; «Запомнить меня» — срок сессии. Регистрация — тот же поток с заголовком «Регистрация».
- Прототип: `authSend`, `authCheck`, `authCodeWire`, `authResend`.

### UC-02 Вход по паролю
- **Триггер:** «Войти с паролем». Пароль есть только у того, кто задал его в профиле.
- **Ошибки:** пароль не задан → «войдите по коду»; 3 неверных → тот же блок. «Забыли пароль?» не ведёт в сброс — возвращает ко входу по коду.
- **API:** `POST /auth/password`; задать/сменить/убрать — `PUT/DELETE /me/password` (от 8 символов). Прототип: `authPw`, `authForgot`, `pfPw`.

### UC-03 Вход через Яндекс ID
- **Шаги:** «Войти через Яндекс ID» → промежуточная страница «Открываем Яндекс ID» → OAuth → новый: UC-04, существующий: кабинет. Привязка в профиле — «Вход и безопасность».
- **API:** `/auth/yandex/start|callback`. **Крайнее:** последний способ входа отвязать нельзя. Прототип: `authYa`, `pfYa`.

### UC-04 Регистрация и знакомство
- **Шаги:** после кода/Яндекс ID — «Давайте знакомиться»: имя*, название кабинета (по умолчанию = имя), «Вы работаете»: агентство / фрилансер / маркетолог в компании → заставка → пустой кабинет (сценарий «новый»: 0 клиентов, приветственный бонус 500 ₽ на балансе).
- **Данные:** User, Cabinet, Membership(own), JournalEntry `+500 «Приветственный бонус»`.
- **API:** `POST /auth/onboarding`. Под кнопками — согласие с условиями и 152-ФЗ. Прототип: `authHello`, `authDone`, `stateApply`.

### UC-05 Выход, сеансы, удаление аккаунта
- Выход → экран входа. Сеансы: список, «Завершить», «Выйти на других устройствах». «Удалить аккаунт…» — подтверждение, 14 дней на отмену входом. «Скачать мои данные» — архив.
- **API:** `/auth/logout`, `/me/sessions*`, `/cabinet/deletion`, `/me/export`. Прототип: `signOut`, `pfEnd`, `pfDelete`, `dlMyData`.

### UC-06 Новый клиент
- **Актор:** М. **Триггер:** «+ Новый клиент» в переключателе, последний пункт любой выпадашки клиента, пустой экран «Завести клиента», первый шаг онбординга, чат «Для кого?», стартовый набор (`pkNewClient`).
- **Шаги:** название* + сайт/соцсеть (необязательно) → клиент сразу текущий, есть во всех выпадашках; стиль — цвета Maker по умолчанию; если дали сайт — снять стиль (имитация).
- **Данные:** Client, Style v1. **API:** `POST /clients` (+ job снятия стиля, если есть ссылка).
- **Ошибки:** пустое название; такое название уже есть → выбираем существующего. Пользователь продолжает с того же места (стратегия → фокус в «Расскажите о клиенте»).
- Прототип: `openNewClient`, `nclGo`, `projAdd`.

### UC-07 Выбор текущего клиента
- Переключатель в сайдбаре: клиент или «Все клиенты». Выбран клиент → списки, Главная, колокольчик (его + общие), чат — только по нему; фильтры клиента на страницах скрыты. Баланс и лимиты не фильтруются.
- **API:** параметр `client` во всех списках; **(предложение)** `PATCH /me {current_client}`. Прототип: `clientSet`, `clientSync`, `clientScope`, `ntfMine`.

### UC-08 Страница клиента
- Шаги Стратегия → План → Публикации; «Ждёт ответа клиента»; «Нужно от вас» (пропуски, правки клиента, черновики тем и публикаций, согласованное к планированию, подключить соцсети из стратегии); последние публикации; ближайшие темы; стиль и голос; соцсети и карты; реклама и аудитории; «Отчёт клиенту каждый месяц».
- **API:** `GET /clients/{id}/home`. Прототип: `renderClientHome`, `flowHTML`, `connPanel`.

## B. Бренд клиента

### UC-09 Рассказ о клиенте → разбор
- **Актор:** М. **Триггер:** «Рассказать о клиенте» (стратегия, страница клиента), «Новая аудитория», «Добавить факты»; текст, голос, файлы, ссылки. «Показать на примере» подставляет образец.
- **Шаги:** текст делится на фразы → люди → **аудитории** (похожие дополняют существующие); цены, адреса, акции, запреты, «о компании» → **факты**; «на вы», «без эмодзи», «с юмором» → **голос** (ползунки, правила); цель с цифрой, «отличаемся тем…», площадки → **стратегия** (только пустые места); ссылки → источники голоса / сайт; нераспознанное — в рассказ стратегии (`brief`). Затем окно «Разобрали рассказ о «…»»: что куда легло со ссылками + «Не хватает» ≤3 вопросов (цель, аудитории, позиционирование, цены, адрес), остальное — «ещё не нашли». Нет стратегии → «Собрать из этого рассказа · 0,82 ₽».
- **Данные:** Audience, Fact, Style.tone/say, VoiceSource, Strategy (пустые поля), Strategy.brief.
- **API:** `POST /clients/{id}/intake` → job → отчёт `{audiences_new[], audiences_updated[], facts_by_cat{}, voice[], strategy_fields[], links[], left}`; `GET …/intake/gaps`; `POST …/intake/answers`.
- **Ошибки:** ничего не распознали → «расскажите подробнее»; пустой текст без файлов — не отправлять.
- Прототип: `ikParse`, `ikApply`, `ikShow`, `ikAnswer`, `ikStrat`, `ikSample`.

### UC-10 База фактов
- Список по категориям, правка прямо в строке (категория угадывается), удаление с «Вернуть». «Разобрать на факты · 0,41 ₽» — вставить текст с сайта/прайса/созвона (сокращения «ул.», «д.» фразу не режут).
- **API:** `/clients/{id}/facts*`, `POST /intake {mode:"facts"}`. Прототип: `renderFacts`, `faEdit`, `faParse`, `delFact`.

### UC-11 «Чего не хватает» — ответ на пропуск
- **Шаги:** список всех `[…]` клиента: сколько раз и где (стратегия, контент-план, посты…) → ввести ответ → «Подставить» → замена **во всех** материалах клиента + факт «Из ответов». Отсюда же «Спросить у клиента» (UC-27).
- **Данные:** тексты Strategy, PlanItem, Publication; Fact(cat «Из ответов»).
- **API:** `GET /clients/{id}/gaps`, `POST /clients/{id}/gaps/fill`.
- **Крайние:** опубликованные материалы не переписываем **(предложение)**; одна плашка в разных материалах — одно значение. Прототип: `faGaps`, `faFill`, `faAnswer`.

### UC-12 Аудитории
- Создание через разбор текста (0,31 ₽, UC-09 в режиме audiences); «Найти на сайте» и «Найти в оплатах CRM» — Maker **предлагает** группу (`sugg`, с причиной) → «Принять»/«Отклонить». Карточка: кто, задача, что важно, возражения, слова, гео, возраст, интересы, оффер, ключевые фразы. Использование: в кампаниях и вариантах страниц; «Убрать из …»; удаление убирает из кампаний и страниц.
- **API:** `/clients/{id}/audiences*`, `/audiences/{id}/accept|decline`, `/clients/{id}/audiences/suggest`.
- **Ошибки:** поиск в CRM при сверке старше 7 дней → «Нужна свежая сверка CRM». Прототип: `grCreate`, `grSuggestSite`, `grFindCRM`, `grAccept`, `grRemoveUse`, `delGroup`.

### UC-13 Стиль
- Источник (сайт / брендбук / готовый набор), логотип, цвета по ролям, шрифты, скругление, плотность, манера фото, эталоны (≤3 принятых кадра). Правка — в черновике с живым превью; плохой контраст (WCAG 4,5:1 / 3:1) → «Показать и подобрать». Сохранение → окно «Что изменится» (опубликованные страницы перекрасятся; баннеры на площадках уйдут на повторную модерацию) → новая версия. Откат — загрузить старую в редактор и сохранить как новую. «Снять заново» с сайта; брендбук PDF; токены CSS/JSON/Figma.
- **API:** `/clients/{id}/style*`. Прототип: `stLoad`, `stSet`, `stImpact`, `stSaveAsk`, `stSave`, `stRollback`, `stRescan`, `stBrand`, `stTokens`.

### UC-14 Голос
- Ползунки тона с живым примером поста; «так говорим / так не говорим»; источники (наш канал / пишем как этот / статья); «Поменять словами · 0,41 ₽» (проще, теплее, строже, без эмодзи, на «вы») → сдвиг ползунков и правила + запись в историю.
- **API:** `GET/PATCH /clients/{id}/voice`, `POST /voice/rewrite`. Прототип: `renderVoice`, `voSay`, `voSrc`, `voAsk`.

## C. Стратегия → план → публикации

### UC-15 Собрать стратегию
- **Триггер:** «Рассказать о клиенте» на экране стратегии, сценарий в чате, онбординг, стартовый набор.
- **Шаги:** рассказ + период (1/3/6/12 мес) → разбор (UC-09) → стратегия-черновик: цель и KPI, позиционирование, главные мысли, площадки с частотой, рубрики с долями (сумма 100%, иначе подсказка). Неизвестное — плашки. Пересборка: новая версия, заполненное не трогаем. Под стратегией — «что дальше» (`strNextHTML`): отправить клиенту / собрать контент-план, не дожидаясь клиента.
- **API:** `POST /clients/{id}/strategy/generate`, `PATCH /strategy`.
- Прототип: `strCreate`, `renderStrat`, `strNextHTML`, `strNext`, `goalClean`.

### UC-16 Отправить клиенту на согласование
- Для стратегии, темы, всех черновиков плана, публикации, страницы. Проверка пропусков → статус «На согласовании» → ссылка скопирована (UC-26). Повторная отправка стирает прошлые правки (`fb`). Маркетолог может сам отметить «Клиент согласовал».
- **API:** `POST …/status {to:"check"}`, `POST /plan-items/send`, `POST /pages/{id}/send`. Прототип: `sendCheck`, `strStatus`, `plStatus`, `plSendAll`, `socStatus`, `pgSend`.

### UC-17 Собрать контент-план
- **Предусловие:** есть стратегия, иначе переход в стратегию. **Шаги:** поводы/акции текстом, период, тем в месяц (8/12/16) → темы с **следующего месяца**: рубрики по долям (метод наибольшего остатка), даты пн/ср/пт, название в нише клиента, главная мысль рубрики, факт из базы или плашка; первая тема — из текста пользователя. Если стратегия скорректирована результатами (UC-36) — чат пишет «учту результаты».
- **Цена:** 0,82 × месяцев. **API:** `POST /clients/{id}/plan/generate`. Вид: список / календарь, выгрузка CSV (BOM, `;`) и Word.
- Прототип: `plCreate`, `plMonths`, `plBank`, `nicheFill`, `plExport`, `dlPlanDocx`.

### UC-18 Тема плана
- Правка названия, мысли, фактов (неизвестное — оранжевым), фото (UC-22), даты; статус; удаление (публикации остаются без ссылки на тему). Значки собранных форматов.
- **API:** `PATCH/DELETE /plan-items/{id}`, `/status`. Прототип: `plOpen`, `plEdit`, `plFact*`, `plImg`, `delTheme`.

### UC-19 Собрать публикацию из темы
- **Триггер:** в теме — «Собрать пост/карусель/сторис/клип»; в «Публикациях» — блок «Темы из контент-плана · N ждут сборки» с «Собрать» и «Собрать все N»; в студии постов — тема из плана.
- **Шаги:** публикация получает тему, мысль, факты, фото; площадки — из стратегии, отфильтрованные по формату (клип: VK + Instagram, сторис: VK + Telegram). Тема уходит из заготовок.
- **API:** `POST /plan-items/{id}/publications`, `POST /plan-items/assemble`. Прототип: `plMake`, `plSocFrom`, `plPlats`, `renderPlanQ`, `pqMake`, `pqMakeAll`, `psFromPlan`.

### UC-20 Пост в студии «чат + пост»
- **Шаги:** новый пост = новый чат: «Про что пост?» (+ темы плана) → черновик под площадки в голосе клиента (0,82). Дальше просьбы в чате: учесть замечание клиента, «+ Telegram» / «без VK», карусель из поста (1,64), вписать значение в пропуск (бесплатно, сохраняется фактом с источником «чат поста»), «добавь факт» (из базы), короче / теплее / строже / другой вариант (0,41, только текущая площадка; «и для всех» — повтор), хэштеги, картинка, «отправь клиенту», «добавь …», «замени … на …», «убери …». Непонятое — честный список того, что умеем. Каждая правка — **новая версия**, старую можно открыть и «Вернуть» (поздние не пропадают). Смена статуса пишется в чат системной строкой.
- **API:** `POST /publications`, `POST /publications/{id}/messages` → `{reply, version?, cost}`, `/versions*`.
- **Крайние:** нет клиента → «Для какого клиента?»; лимит площадки превышен → «длиннее на N знаков» + «Сократить».
- Прототип: `psCreate`, `psSend`, `psParse`, `psRestore`, `socShorten`.

### UC-21 Карусель, сторис, клип
- Создание через сценарий в чате (UC-44): тема, площадки; карусель — число слайдов (5/7/10; обложку и последний слайд не удалить); сторис — кадров (3/4/6), безопасные зоны, стикер-ссылка; клип — длительность 15/30/60 с: сначала **раскадровка** (0,41), рендер — отдельно (41,03, с подтверждением) → «Ждёт проверки» + уведомление «Клип готов».
- **API:** `POST /publications`, `PATCH`, `POST /publications/{id}/render`. Прототип: `socCreate`, `socSlide*`, `socFrame*`, `socScene*`, `socRender`.

### UC-22 Картинка в публикации или теме
- «Поменять»: из фото клиента (принятые, свои, ждущие проверки) / «Сгенерировать» (промпт из темы, 7,38 ₽, кадр уходит в «Фото и видео › Для публикаций») / «Загрузить свою» (в «Свои фото»). Для сторис — фон кадра, для клипа — кадр сцены.
- **API:** `PATCH /publications/{id} {img}`, `POST /clients/{id}/shots/generate`, `/uploads`. Прототип: `socImg`, `plImg`, `imgPick`, `ipGen`, `ipUp`.

### UC-23 Подключить соцсеть или карту клиента
- **Где:** страница клиента («Соцсети и карты клиента»; площадки из стратегии — «в стратегии»), дело в «Нужно от вас», кнопка в стратегии, окно публикации, входящие, рейтинг отзывов.
- **Сценарии:** VK, Instagram, LinkedIn, YouTube — «Откроется … пароль мы не видим» → OAuth → выбор сообщества/страницы. Telegram — добавить @MakerPostBot админом с правом «Публиковать сообщения» + ссылка `t.me/…` → проверка. TenChat — «Включить напоминания» (`remind`). 2ГИС, Яндекс Карты — вход владельцем карточки, право читать отзывы и отвечать. Ограниченные в РФ — предупреждение. После подключения — возврат в исходное окно.
- **API:** `/clients/{id}/connections/*`, `/oauth/{platform}/callback`. **Ошибки:** неверный формат ссылки Telegram; бот не админ; OAuth отменён. Отключение → дальше напоминания.
- Прототип: `connOpen`, `connOauth`, `connTg`, `connDone`, `connOff`, `connPanel`, `connMissing`.

### UC-24 Запланировать и опубликовать
- **Предусловие:** публикация «Согласован». **Шаги:** «Запланировать» → выбор времени (в прототипе 4 пресета: завтра 10:00/19:00, пятница 12:00, суббота 11:00; подсказка «лучшее время по прошлым публикациям») + по каждой площадке: подключена — «опубликуем сами», нет / remind — «пришлём напоминание с текстом и картинкой» + «Подключить» → «Запланирован». «Снять с расписания» → «Согласован». «Опубликовать сейчас»: подключённые — сразу, остальные — текст и картинка в буфер.
- **С (в назначенное время):** публикация в `auto`-площадки; `remind` — напоминание маркетологу; успех → «Опубликован».
- **API:** `/publications/{id}/schedule|unschedule|publish`, `GET /publish-plan`. Прототип: `socSchedule`, `socSchedNote`, `socScheduleGo`, `socPublishNow`, `socPubAsk`, `socPublishGo`, `socSplit`.

### UC-25 Сбой публикации → «Переподключить»
- **С:** площадка отклонила, доступ истёк (`CONN.exp`) → статус «Не вышел» (`fail{pl, why}`), уведомление + напоминание первым «Пост … не вышел в VK».
- **М:** открыть пост → «Переподключить VK и опубликовать» → OAuth (UC-23) → повтор публикации → «Опубликован».
- **API:** `POST /publications/{id}/retry`. **Крайние:** повтор после переподключения должен быть идемпотентным (не задвоить пост). Прототип: `socFix`, `socReconnect`, `socRetry`, `todayExtra`.

## D. Клиент по ссылке

### UC-26 Согласование клиентом по ссылке
- **М:** «Ссылка для клиента» (страница клиента, публикация, «Отправить клиенту») → окно со ссылкой `maker.app/c/xxxxxx`, «Скопировать», «Открыть как клиент».
- **К:** открывает без входа; шапка в цветах клиента, «Материалы от команды «…»»; видит **только ждущее его решения**: вопросы от команды → стратегия → темы плана → публикации (макет площадки, переключение площадок, «Весь текст») → страницы. Пропуски — «уточняем». По каждой: «Согласовать» или «Нужны правки» (комментарий обязателен). «Решено N из M», «Готово — спасибо», решение можно отменить.

### UC-49 Удаление с «Вернуть»
- Удалить можно всё создаваемое: кадр, серию, ролик, комплект, кампанию, колоду, чат, аудиторию, страницу, публикацию, тему, стратегию, факт, шаблон, клиента целиком. Окно «Удалить «…»?» со списком последствий (где используется, что снимем с показа, что останется) → тост 8 секунд «Вернуть» — всё обратно, включая связи.
- **Правила:** идущую кампанию и клиента с идущими кампаниями — нельзя; опубликованный пост в соцсети остаётся («удалить можно только в площадке»); опубликованная страница снимается с сайта; баннеры на площадке снимаются с показа; ссылки для клиента перестают открываться.
- **API:** мягкий `DELETE` + `POST /undo/{token}`. Прототип: `delAsk`, `delRun`, `delUndo`, `delDone`, `del*`.

### UC-50 Выгрузка файлов
- Уже работает в браузере: PNG баннеров/слайдов/сторис, Word стратегии и плана, CSV (план, журнал, расходы, результат), PowerPoint и PDF колоды, HTML лендинга, ZIP, токены. Только движок: MP4 роликов и клипов, закрывающие документы (`data-engine`). Имена файлов — по-русски по смыслу («Стратегия — Вита.docx»).
- **API:** `…/export` эндпоинты; решение «браузер или сервер» — open-questions. Прототип: `saveFile`, `engineFile`, `dl*`.
