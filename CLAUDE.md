# Maker — правила UI прототипа

Действуют для `prototype.html` и любых новых экранов Maker. Новая страница собирается **только из этих компонентов**; если нужного нет — сначала добавить его сюда, потом верстать. Значения берутся из токенов `:root` (`--blue`, `--line-2`, `--ok-bg`…), не хардкодом.

## Модель: пользователь → его клиенты (с 2 окт 2026)

- **Кабинет принадлежит маркетологу** (агентство, фрилансер). Внутри — **клиенты**, которых он ведёт. Слово «проект» в интерфейсе не используем: «Клиенты», «Клиент:», «Новый клиент», «Все клиенты».
- **Текущий клиент — один на весь кабинет** (`CLIENT`, `mk-client`): переключатель в левом верхнем углу («Клиент · Вита», меню с цветными метками, «ждёт ответа: N», «+ Новый клиент», «Все клиенты списком»). Все фильтры и выпадашки «Клиент:» следуют за ним (`clientSync`). Новый клиент сразу становится текущим. Название кабинета — только в меню аватара и в подписи для клиента («Материалы от команды …»).
- **Страница клиента — его дом** (`renderClientHome`, только из данных): шаги Стратегия → План → Публикации, «Ждёт ответа клиента», «Нужно от вас» (правки, черновики, согласованное к планированию), последние публикации, ближайшие темы, стиль и голос, реклама и аудитории. Кнопки: «Ссылка для клиента», «Новая задача».
- **Словарь:** Клиенты · Аудитории (не «группы покупателей») · Стиль и голос (не «дизайн-код/оформление»). Неизбежные термины (erid, ОРД, ROMI, CRM, коллтрекинг, UTM, CTR, рубрики, охват, цена заявки, мастер-баннер, безопасные зоны) получают пунктирное подчёркивание и подсказку по наведению/фокусу (`GLOSS`, первое упоминание на экране).
- **Генерация слушает:** цель стратегии берётся из рассказа; «Предложить аудитории» по нише клиента; темы плана — с главной мыслью рубрики и словами ниши; пост из темы собирается из её мысли и фактов. Плашка `[…]` — только для действительно неизвестного.
- **Перед отправкой клиенту** — окно «Осталось пропусков: N» (заполнить / отправить как есть). Клиент вместо `[…]` видит серое «уточняем».
- Моделей нейросетей в интерфейсе нет. Площадки, ограниченные в РФ, — в конце списка с подписью «огр. в РФ». В превью площадок — без выдуманных лайков и подписчиков. Цена страницы — 2,25 ₽ везде.

## Выгрузка материалов — настоящие файлы, не имитация

- Всё сохраняется через `saveFile(имя, данные)`: в артефакте — capability `downloads` (окно подтверждения), локально — обычная ссылка. Имена файлов — по-русски, по смыслу: «Стратегия — Вита.docx», «Итоги III квартала.pptx».
- Что выгружается: **баннеры** — архив PNG всех включённых размеров × вариантов текста (рисуются на canvas в стиле клиента, с маркировкой); **карусель** — PNG слайдов под пропорцию площадки, для LinkedIn — PDF; **сторис** — PNG 1080×1920, текст в безопасной зоне; **клип** — раскладка .txt, субтитры .srt, кадры сцен; **пост** — тексты для каждой площадки и картинка; **стратегия** и **контент-план** — Word (.docx), план ещё и CSV для Excel; **презентация** — PowerPoint (с заметками докладчику) и PDF; **лендинг** — один HTML со стилями и картинками внутри; **кадры** — JPG и архив серии; **токены стиля** — JSON/текст; **журнал, расходы по клиенту, результат** — CSV для Excel; **мои данные** — архив.
- Файлы, которые отдаёт только движок (ролики MP4 — клипы и видео, закрывающие документы — квитанции, акты, УПД, счета), — **обычная кнопка «Скачать» на своём месте** с меткой `data-engine` (`clip-mp4`, `video-mp4`, `billing-doc`) и вызовом `engineFile()`. Разработчик находит все такие места поиском по `data-engine` и подключает выдачу файла.
- Без библиотек: ZIP (без сжатия) и DOCX собираются своим кодом. С библиотеками по требованию: PDF — jsPDF с cdnjs, PowerPoint — PptxGenJS с jsDelivr (на cdnjs этой версии нет). Нет сети — честное «не получилось загрузить модуль».

## Бренд: Стиль · Голос · База фактов · Шаблоны · Аудитории

- **Стиль** — визуальное: цвета, шрифты, скругления, фото (`DESIGN`). **Голос** — как клиент говорит: два ползунка (дружелюбно↔официально, сдержанно↔эмоционально) с живым примером поста, «так говорим / так не говорим», источники голоса (наш канал / пишем как этот / статья) и «Поменять словами» (проще, теплее, строже, без эмодзи, на «вы» → меняются ползунки и правила, запись в историю). Тон хранится в `DESIGN[клиент].tone` — один источник для Стиля и Голоса.
- **База фактов** (`FACTS`) — что знаем наверняка, по разделам: о компании, цены и условия, адреса и время, цифры и результаты, акции, запреты, из ответов. Факт правится прямо в списке. Текст с сайта/прайса/созвона разбирается на факты (`faParse`, сокращения «ул.», «д.» не режут фразу).
- **«Чего не хватает»** — все плашки `[…]` из стратегии, плана и публикаций клиента, с тем, сколько раз и где встречаются. Ответ один раз → подставляется **во все материалы** клиента и сохраняется фактом («Из ответов»). На странице клиента в «Нужно от вас» — «Ответить на N вопросов о клиенте».
- Генерация берёт факты из базы: позиционирование стратегии, факты тем плана, цифры в постах. Плашка появляется только когда факта нет.
- Разметка: каждая `section.view` — прямой ребёнок `.content`. Проверка после правок вёрстки: `[...document.querySelectorAll('section.view')].filter(s=>s.parentElement.className!=='content')` должен быть пуст (ловили: незакрытый div выкинул полсайта из колонки).

## Направление (с 1 окт 2026)

- Maker — для маркетолога, который ведёт клиентов; главное — **коммуникации и соцсети** (стратегия → контент-план → посты, карусели, сторис, клипы; баннеры), сайты и презентации — вторично («Ещё»).
- Снимок до перестройки: `prototype-v1.html` → https://claude.ai/artifact/FzrGXDzSxDt61zu5MZsqJD. Его не трогаем.
- **Главная — чат-first:** окно чата с «печатающимися» подсказками (как будто набирает человек), ввод любым способом (текст, голос, файлы, картинки, ссылки), выбор проекта; ниже «Что делаем сегодня» — единый список из сигналов (`renderToday`), у каждого дела кнопка «Сделать», которая набирает задачу в чат. Остальное — дашборд.
- **В окне ввода на Главной нет выбора проекта** — у маркетолога в начале может не быть ни одного. Клиент берётся из текста («для Виты» → проект «Вита»), из дела «Сделать» или спрашивается в чате первым ответом «Для кого делаем?» (кнопки проектов + «Новый клиент» + «Ответь в общем»). Подсказки и чипы «С чего начать» не подставляют проект: чип набирает фразу до «…для » и оставляет курсор — клиента дописывают сами. Чат без проекта — «Без проекта» в списке, без контекста и без действий, которым нужен дизайн-код (кадр, баннеры, страница); вопрос «для кого» бесплатный.
- **Новый клиент — из любого выбора проекта.** Каждая выпадашка проекта (`select[data-projs="pick"]`) последним пунктом даёт «+ Новый клиент» → окно `#newcl-modal` (название обязательно, сайт/соцсеть — по желанию) → `projAdd()` заводит проект везде сразу: карточки, все выпадашки, дизайн-код в цветах Maker по умолчанию. После этого человек продолжает с того же места (выпадашка выбирает нового клиента; в стратегии — пустая стратегия и фокус в «Расскажите о клиенте»; в чате — ответ в контексте нового клиента). «Новый проект → С нуля» ведёт туда же. Никаких действий, которые требуют заранее существующего проекта.
- Модели нейросетей в интерфейсе не показываем (не агрегатор): выбор — «быстрее/лучше».
- **Заставка при входе** (`#intro`) — ~6,3 с, **только при первом входе и после «Выйти из кабинета»** (флаг `mk-intro` в localStorage; `?intro` в адресе — показать принудительно для демо). Обновление страницы её не показывает: камера летит сквозь облако карточек (фото `img/intro/01–08.jpg` + живые кусочки UI), по центру 8 героев по ~0,48 с (чат → дизайн-код → пост → карусель → сторис → баннер → контент-план → клип), финал — логотип maker (~2 с) с «дышащим» синим свечением на белой подложке, облако приглушено и размыто, затем растворяется в Главную. CSS-анимации стоят на паузе до класса `.go`, который ставит скрипт, — чтобы не расходились с таймерами. При `prefers-reduced-motion` — только логотип ~1 с. Картинки генерятся без текста, подписи — кодом.

## Логотип

- Знак Maker — один SVG-символ `#mk-logo` (синий скруглённый квадрат + три полупрозрачные карточки с наклоном `skewY(18)`), вставлен в начале разметки. Везде подключаем через `<svg viewBox="0 0 100 100"><use href="#mk-logo"/></svg>`, не рисуем заново. Надпись «maker» — Onest 800, `#141A2A`.

## Оформление оболочки (с 2 окт 2026)

- **Сайдбар синий** (градиент `#2C6BF2 → #1747CF`), текст и иконки белые; активный пункт — светло-синяя пилюля с тенью, активный подпункт — `rgba(255,255,255,.16)`. Переключатель проекта и карточка профиля — «стекло»: `rgba(255,255,255,.12–.14)` + белая рамка `.26`.
- **Стеклянные фигуры** — SVG из скруглённых карточек `skewY(-12)` (как в логотипе): справа вверху Главной (`.hero-glass`, за текстом) и внизу сайдбара (`.side-art`). Фигуры в сайдбаре живут **внутри подвала** и занимают только свободное место под меню: на невысоком экране сжимаются до нуля, а не наезжают на пункты. Белый текст поверх стекла не кладём никогда.
- **Скрыть меню:** на десктопе кнопка-панель справа от логотипа (`.side-x`) прячет сайдбар, в шапке появляется такая же кнопка (`.side-tg`), чтобы вернуть; состояние запоминается. На ≤900px сайдбар — выезжающая панель: бургер в шапке, затемнение, закрытие по ✕, по фону, по Esc и по выбору пункта.
- Главная: заголовок до 66px, «сегодня?» синим; «Что делаем сегодня» — показываем 3 дела, «Показать ещё N →» ссылкой справа в заголовке блока; у каждого дела меню «⋯» (Отложить до завтра / Уже сделано) и синяя «Сделать». «Недавнее» — карточки с цветной иконкой и круглой стрелкой справа.

## Контент: стратегия → контент-план → публикации

- Цепочка работы: **Стратегия** (что, кому, зачем) → **Контент-план** (темы на даты) → **Соцсети** (тема упакована в пост, карусель, сторис, клип). Наверху обеих страниц — полоса шагов `.flow` с состоянием каждого шага проекта, по клику переход.
- Стратегия — одна на проект в `STRATS[проект]`: цель и метрики, аудитории (только из `GROUPS`), позиционирование и главные мысли, площадки и частота, рубрики с долями (сумма 100%, иначе красная подсказка), голос (из `DESIGN`). Чего не знаем — плашки `[…]`. Статусы как у публикаций: Черновик → На согласовании → Согласована. Нет стратегии — пунктирный блок «Стратегии пока нет» и панель «Расскажите о клиенте».
- Тема контент-плана (`PLAN`) — это и есть «материал»: дата, рубрика из стратегии, название, главная мысль, факты (неизвестное — оранжевым пунктиром), фото из «Фото и видео» проекта, статус. Вид — Список и Календарь (на ≤900px календарь становится списком дней с темами).
- План собирается **только из стратегии**: рубрики раскладываются по долям (метод наибольшего остатка), даты — пн/ср/пт месяца, темы приходят черновиками. Без стратегии кнопка ведёт в «Стратегию».
- Из темы — «Собрать» пост/карусель/сторис/клип: публикация получает `th` (ссылку на тему), текст, факты и фото темы; в редакторе публикации — ссылка «из темы контент-плана →». В строке темы — значки собранных форматов.
- «Скачать для Excel» — CSV с BOM и `;` (открывается в Excel и Google Таблицах) по текущим фильтрам. «Отправить черновики клиенту» — все черновики списка одной ссылкой.
- Сигналы на Главную: стратегия ждёт клиента; согласованная стратегия без плана на следующий месяц; темы ждут согласования.
- «Фото и видео» — один пункт меню, внутри вкладки Фото | Видео (две вьюхи `images`/`video`, `NAVMAP.video='images'`).

## Соцсети

- Меню (с 5 окт): Главная · Клиенты · Чаты → **Контент** (1 Стратегия · 2 Контент-план · 3 Публикации · Фото и видео · Сайты и страницы · Презентации) → **Реклама** (Баннеры · Кампании · Результат) → **Бренд клиента** (Стиль · Голос · База фактов · Аудитории · Шаблоны) → Счёт и оплата. Группы — аккордеон: открыта одна, та, где вы сейчас. «Публикации» — один пункт, внутри вкладки Посты | Карусели | Сторис | Клипы (`.pubtabs`, `NAVMAP` подсвечивает пункт на любом формате). Снимок до этой перестройки — `prototype-v2.html` и git-метка `do-uprosheniya`.
- Одна модель `SOC` для всех четырёх форматов; правила площадок — только в `SOC_FMT` (размер, пропорция, лимит текста, хэштеги, безопасные зоны, вид ссылки). Лимит превышен — честное «длиннее на N знаков» и «Сократить», а не молча обрезать.
- Одна тема → версии под каждую выбранную площадку; превью — макет самой площадки (VK, Telegram, Instagram, TenChat, LinkedIn). Instagram/LinkedIn/YouTube — с честной пометкой об ограничениях в РФ.
- Сторис и клипы — с переключателем «Показать безопасные зоны»; текст и кнопка-ссылка всегда внутри зоны площадки.
- Клип: сначала раскадровка (дёшево, правится), рендер — отдельной кнопкой через `spendGate`.
- Статусы публикаций: Черновик → На согласовании (оранжевый, ждёт клиента) → Согласован (зелёный) → Запланирован (`.st.proc`) → Опубликован (`.st.done`). Соцсети не подключены — публикация честно говорит «скопировали текст и картинку».

## Слои экрана: понять → сделать → цифры (с 5 окт 2026)

Задача — чтобы человек «не в теме» зашёл, понял, что он делает и зачем, и только потом пошёл в цифры. Ничего не удаляем: таблицы, воронки, журналы остаются, к ним подводим.

1. **Зачем этот экран** — `.ph-why` под заголовком: одна-две фразы человеческим языком.
2. **Итог словами** — `.sum-card` (фраза из тех же данных, что цифры ниже, + `.verdict`). Никаких отдельных расчётов: если цифры и фраза могут разойтись — фраза неправильная.
3. **Что стоит сделать** — список сигналов с кнопками (`.step-h` + `.ins-list`).
4. **Главные цифры** — 4–5 показателей; термин остаётся, но подпись понятная («Окупаемость», под ней «ROMI: …» — сработает подсказка `GLOSS`).
5. **«Подробно»** — `.deep[data-deep=…]`: кнопка-полоса с описанием, что внутри; под ней источники, воронка, графики, таблицы, выгрузка в Excel. Состояние запоминается (`localStorage mk-deep`), повторно человек сразу видит раскрытым.

Одно и то же не повторяем в двух слоях (ловили: «продажи учтены по 28 сен» и в итоге, и в делах — оставили в делах, там кнопка). Пилот — «Результат».

## Где я: крошки, «назад», адрес

- В шапке всегда крошки `#crumb` (кроме Главной): **‹ назад** · Главная › группа меню › раздел › карточка. Группа — серый текст, раздел — ссылка на список, текущее — жирным с многоточием. Иерархия — одна таблица `NAVH` (вид → группа, название, родитель).
- «Провалиться» в карточку = новый уровень: отдельные страницы (проект, презентация, кампания, страница сайта) и карточки внутри раздела (пост, карусель, сторис, клип, тема плана, комплект баннеров, чат) пишут себя в крошки через `routeDetail(id, название)`. **Стрелка «‹» — туда, откуда пришли** (своя история переходов `NAVST` в sessionStorage, подсказка «Назад: Стратегия»): Стратегия → Контент-план → тема → пост, назад — в обратном порядке; смена проекта на той же странице шагом не считается. Если истории нет (открыли ссылку сразу) — на уровень выше: из карточки в её список, из раздела на Главную. Ссылки в крошках — всегда по уровням (`routeUp`).
- Адрес хранит место: `#/вид/id?p=проект` + копия в localStorage `mk-route`. Обновление страницы возвращает туда же (раздел, открытая карточка, выбранный проект); кнопка «назад» браузера ходит по истории. Карточки, созданные в этой сессии, после обновления не живут (нет бэкенда) — открывается их список.
- На ≤900px в крошках остаются «‹», раздел и карточка, в одну строку с многоточием.
- Меню профиля (аватар в шапке и «Демо-кабинет» внизу меню): «Профиль и доступы», «Выйти из кабинета» — выход сбрасывает место и заставку.

## Состояния (для передачи в разработку)

- **Сценарии данных** — `STATE`: `new` (Новый пользователь: 0 клиентов, баланс = приветственный бонус 500 ₽), `first` (Первые шаги: 1 клиент, ничего больше), `active` (рабочий кабинет), `broke` (рабочий, баланс 0 ₽). Включаются из панели «прототип · демо-режим» (правый нижний угол), `?state=…` в адресе или «Картой состояний». Смена сценария перезагружает страницу с чистыми данными (`stateApply()` опустошает массивы).
- **Пустые экраны решаются данными, а не флагом** (`stateEval()` после каждого перехода и платного действия): нет ни одного клиента → в любом разделе (кроме Главной, Счёта, Карты) один блок `.ns-empty` «… появится, когда заведёте клиента» + «Завести клиента», остальное скрыто; клиент есть, а в разделе пусто → `.ns-empty` с объяснением, откуда берутся материалы, а панель создания остаётся видна. Первое действие убирает пустой экран сам.
- **Главная у нового кабинета:** вместо «Что делаем сегодня» — «Первые шаги N из 4» (клиент → стратегия → контент-план → первый пост), текущий шаг с «Сделать», пройденные — «Готово», будущие — «Потом»; «Недавнее» скрыто; в «Проектах» — карточка «+ Новый клиент». Шаги держатся, пока не пройдены все четыре.
- **Деньги кончились:** полоса `#bal-bar` над контентом на всех страницах («Генерация на паузе — черновики, правки и согласования работают» + «Пополнить»), первым делом на Главной то же; платное ведёт в окно пополнения (`spendGate`).
- **Системные состояния** (`SYSST`, любой экран): Загрузка — серые заглушки с переливом вместо контента; Ошибка — «Не получилось загрузить «…»», «черновики не пропали», «Повторить» + «Написать в поддержку»; Нет сети — полоса `#net-bar`, данные видны, кнопки генерации приглушены.
- **Карта состояний** (`#/states`): таблица «экран × состояние», каждая ячейка открывает экран в нём. Новый экран = новая строка в `MAP_ROWS`, новое пустое состояние — запись в `NS_TXT`.

## Вход

- **Без пароля.** Почта или телефон (переключатель-чипы) → код из 4 цифр → в кабинет. Или «Войти с Яндекс ID» (своя промежуточная страница «Открываем Яндекс ID», чужие экраны не рисуем). Под кнопками — согласие с условиями и обработкой персональных данных (152-ФЗ).
- Код: 4 поля, автопереход, вставка целиком, автопроверка. Неверный — «осталось N попытки» и встряска; 3 ошибки → «Слишком много попыток», ждать 10 минут. «Отправить ещё раз» через 45 с. «← Изменить почту/номер». Телефон маскируется `+7 (___) ___-__-__`, в подтверждении — со звёздочками.
- **Новый человек** после кода или Яндекс ID → «Давайте знакомиться» (имя — обязательно, название кабинета, «Вы работаете»: агентство / фрилансер / маркетолог в компании) → заставка → пустой кабинет (`state=new`) с его именем в аватаре, приветствии и названии кабинета. **Существующий** → заставка → свой кабинет.
- «Выйти из кабинета» → экран входа (`mk-auth=out`). Заставка — после входа, не перед ним.
- **Вход с промо-лендинга:** `prototype.html?login` — то же состояние, что после «Выйти» (скрипт перед первым `<script>` страницы ставит `mk-auth=out`, сбрасывает место и убирает `login` из адреса; метки `utm_*` остаются). Все кнопки «Попробовать/Начать бесплатно» и «Войти» в `landing.html` ведут сюда (`a[data-login]`). Внимание: единственный `</head>` в файле — внутри JS-строки выгрузки лендинга, вставлять «в head» по нему нельзя.
- В демо: код всегда 1234, переключатель «войти как новый / уже с кабинетом». Все 10 состояний входа — в «Карте состояний» и «Экран входа» в панели демо-режима.

## Уведомления и напоминания — разные вещи

- **Уведомления = что случилось** (без вас): клиент согласовал / просит правки, площадка отклонила или пропустила баннеры, клип или сборка готовы, баланс ниже порога, коллега принял приглашение. Живут в **колокольчике** в шапке на любой странице (`NTF`, `ntfPush`): красный счётчик непрочитанных, лента свежими сверху, у непрочитанных синий фон и точка, клик — открыть то, о чём уведомление, «Прочитать все», шестерёнка → Профиль › Уведомления. Пусто — «Пока тихо» с объяснением. На ≤600px лента на весь экран с ✕.
- **Напоминания = что сделать вам**: на Главной блок «Напоминания» без большого счётчика, максимум 3, дальше тихая ссылка «Ещё N»; у каждого «Сделать/Открыть» и «⋯ Отложить / Уже сделано». Нет дел — блока нет (не «На сегодня всё»). У нового кабинета на этом месте «Первые шаги».
- Ответ клиента по ссылке и готовый клип сразу пишут уведомление; правки клиента — ещё и напоминанием.

## Профиль (`#/profile`, меню аватара → «Профиль и доступы»)

- Вкладки: **Профиль** (фото или буква, имя, фамилия, «Вы работаете»; «Сохранить/Отменить» активны только после правки; контакты для входа — смена почты/телефона через код; часовой пояс; «Скачать мои данные», «Удалить аккаунт…» с подтверждением-переключателем и 14 днями на отмену) · **Вход и безопасность** (способы входа: код на почту, по SMS, Яндекс ID — последний способ отвязать нельзя; сеансы с «это устройство», «Завершить», «Выйти на других устройствах») · **Уведомления** (в кабинете — всегда; таблица «событие × почта/Telegram», Telegram — после подключения бота; тихие часы) · **Команда и доступы** (участники с ролями Владелец/Редактор/Просмотр/Бухгалтер, приглашённые — «приглашён», «Отозвать»; форма приглашения по почте; «Кто что может»). Клиенты по ссылке мест не занимают.
- Имя, фамилия и фото сразу видны в аватаре шапки и в карточке внизу меню. У нового пользователя профиль заполняется из знакомства при входе.
- Класс `.cv` занят шевронами меню — оверлеи и новые блоки не называем общими короткими именами (ловили: экран клиента сломал стрелки; шаг входа «au-code» сломал карточку).

## Роль «Клиент по ссылке»

- Отдельный экран `#cv` поверх всего, адрес `#/client/<проект>`: без меню, входа и цен. Шапка — в цветах клиента (его логотип-буква и название), «Материалы от команды «…»».
- Показывает **только то, что ждёт решения** этого клиента (`cvPending`): стратегия → темы плана → публикации. Каждая карточка — превью как в кабинете (макет площадки с переключением площадок и «Весь текст», слайды и кадры лентой, раскладка клипа, тема с фактами, стратегия коротко), под ней «Согласовать» и «Нужны правки» (поле комментария, отправка только с текстом). Сверху «Решено N из M», в конце «Готово — спасибо». Решение можно отменить.
- Ответ сразу меняет данные кабинета: согласовано → статус «Согласован(а)»; правки → «Черновик» + `fb` (текст клиента). В кабинете правки видны оранжевой плашкой «Клиент просит правки: «…»» в редакторе и **первыми** в «Что делаем сегодня»; согласованный пост — «Клиент согласовал… → Запланировать». Повторная отправка на согласование стирает старый `fb`.
- Состояния экрана: есть что согласовать · «Сейчас нечего согласовывать» · «Ссылка больше не действует». Все — в «Карте состояний» и в панели демо-режима (роль).
- Кнопка «Ссылка для клиента» в кабинете открывает окно со ссылкой (`maker.app/c/xxxxxx`, латиница), «Скопировать» и «Открыть как клиент».

## Каркас страницы-раздела

Порядок сверху вниз, без перестановок:

1. `.phead` — `h1` слева, `.sp`, справа кнопки: вторичные `.pbtn.ghost` → последней `.showbtn` «Показ».
2. `.itabs` / `.itab` (если у раздела есть подвиды). Счётчик — `<span class="cnt">` моно-шрифтом.
3. `.toolbar` — фильтры (см. ниже).
4. `.empty-hint` — одна-две фразы, объясняющие логику раздела (не «добро пожаловать»).
5. Контент: таблица `.tbl`, сетка карточек `.mgrid`/`.cards` или список строк.
6. `.create-panel` — панель создания всегда внизу раздела.

Липкие элементы: только боковое меню (`.side`) и заголовок внутри модалки (`.modalhd`). Шапка страницы (`.topbar`) и всё в контенте **не липнут** — прозрачная шапка поверх прокручиваемого контента наезжает на него. Если нужно прокрутить к блоку — `scroll-margin-top:16px`, без поправок на шапку.

## Тулбар фильтров

Порядок элементов: поиск `.tsearch` → выпадашка проекта (`select.sortsel.fsel`, первый пункт «Все проекты») → статусы `.chipset` из `.chip` → сортировка `select.sortsel` (прижата вправо).

- Фильтры **работают по-настоящему** (рендер из массива данных), а не показывают toast-заглушку.
- Чипы статусов = реальные статусы в данных, первый всегда «Все». Счётчик «требует внимания» внутри чипа — `.ccnt` (оранжевый, пустой скрывается).
- При пустом результате — строка/блок «Ничего не нашли… **Сбросить фильтры**» (`.empty-row` в таблице, `.img-empty` в сетке), ссылка сбрасывает всё.
- Выбор проекта в фильтре синхронизирует проект в `.create-panel` (`syncTarget`).
- ≤900px: поиск на всю ширину, остальное переносится; `margin-left:auto` у сортировки снимается.

## Выпадашки (dropdown)

- **Нативный вид `<select>` не показывать никогда** — ни стрелку, ни системный список. В разметке пишем обычный `<select class="sortsel">` / `<select class="cp-sel">`, скрипт превращает его в `.dd`:
  - кнопка `.dd-btn`: белый фон, `1px var(--line-2)`, радиус 10px, паддинг `8px 11px 8px 14px`, 13px/500, шеврон 14px `var(--ink-3)`, при открытии — синяя рамка + кольцо `0 0 0 3px var(--blue-softer)`, шеврон поворачивается на 180°;
  - список `.dd-menu`: белый, радиус 12px, мягкая тень, паддинг 5px, пункт `.dd-opt` 13.5px, у выбранного синий текст + галочка; анимация 140ms ease-out от точки открытия; открывается вверх/вправо, если не помещается;
  - клавиатура: ↓ открывает, ↑↓ по пунктам, Esc закрывает (не закрывая модалку под ним), клик вне — закрывает.
- Варианты: `.sortsel` → прямоугольная кнопка тулбара; `.sortsel.fsel` → без авто-отступа (фильтр); `.cp-sel` → пилюля `.dd-pill` (радиус 20px, 600) внутри `.create-panel` и модалок («Собрать в:», «В проект:»).
- Значение читаем/пишем через `select.value` — подпись кнопки обновляется сама.
- **Ширина не прыгает.** Кнопка выпадашки всегда шириной по самому длинному варианту (все варианты лежат в `.dd-val` в одной ячейке grid, видим только выбранный) — при смене значения ни она, ни соседи не сдвигаются. Потолок 240px, дальше многоточие.
- То же для любых кнопок, чья подпись меняется после выбора (напр. «Первый кадр: …» — `.cf-name` фиксированной ширины с многоточием). Проверка: перебрать все значения и сравнить `getBoundingClientRect().width` — должна совпадать.

## Состояние «выбрано» — должно читаться без усилий

Выбранное отличается **заливкой и значком**, а не оттенком или обводкой (обводка = фокус клавиатуры, путать нельзя).

- Одиночный выбор из набора (чипы-фильтры, «Вариант 1/2/3») — `.chip.on`: сплошной `--blue`, белый текст 600. Невыбранные — белые с серой рамкой.
- Мультивыбор (форматы 9:16 / 1:1 / 16:9, размеры) — `.fmt-tg`: выбранный — синяя заливка + белая галочка ✓, невыбранный — белый + серый плюс. Всегда `aria-pressed`. Минимум один включён.
- Выбор картинки (фон баннера, первый кадр) — синяя рамка + круглый синий значок с галочкой в правом верхнем углу.
- Пункт в выпадашке — синий текст + галочка (`.dd-opt.on`). Вкл/выкл — переключатель `.toggle`.
- Запрещено: «выбрано» = светло-голубой фон + чуть другой цвет текста; выбор, понятный только по сравнению с соседями.

## Плашки (pills)

Одна система, одна геометрия: 12px/600, паддинг `4px 10px`, радиус 20px, точка-индикатор слева, `white-space:nowrap`.

| Класс | Смысл | Цвет |
| --- | --- | --- |
| `.st.pub` | опубликовано / принято | `--ok-bg` / `--ok-ink` |
| `.st.check` | ждёт решения / на проверке | `--warn-bg` / `--warn-ink` |
| `.st.draft` | черновик | `--set-bg` / `--set-ink` |
| `.st.redo` | переснято / обновлено по замечанию | `--set-bg` / `--set-ink` |
| `.st.bad` | брак / ошибка | `#FCE9E7` / `#A33A2E` |
| `.st.own` | загружено пользователем | `#F1ECFB` / `#5B3FA0` |
| `.st.run` | кампания идёт | `--ok-bg` / `--ok-ink` |
| `.st.pause` | на паузе (решение пользователя) | `#EDEFF3` / `#5B6472` |
| `.st.done` | завершено, архив | `#F1F3F7` / `#8E97AC` |
| `.st.proc` | в работе у системы или площадки (рендер, модерация) — от пользователя ничего не нужно | `--blue-softer` / `--blue-ink` |
| `.sck.ok/.wait/(пусто)` | состояние подключения (домен, HTTPS, Метрика, коллтрекинг) | ok / warn / серый `--inset` |

- **Одна шкала слов для статусов** (с 2 окт): Черновик → **Ждёт проверки** (вы принимаете результат нейросети: кадр, ролик, страница, план колоды) → **На согласовании** (ждём клиента) → Согласован/Принят → **На модерации** (площадка) → Запланирован → Опубликован/Работает. Отказы: **Не получился** (кадр — переснимем бесплатно), **Отклонён площадкой**, «Клиент просит правки». Слова «Ждёт решения», «На проверке», «Брак» не используем.
- Оранжевый (`warn`) — только то, что ждёт действия пользователя. Красный — только брак/ошибка. Зелёный — только «готово».
- Новый статус = новая строка в таблице выше, а не новый ad-hoc цвет.
- На фото плашка статуса — `.badge-st` в левом верхнем углу, отступ 16px от края карточки.
- Известное расхождение: `.pstat` на карточках проектов (12.5px, `5px 12px`, свои цвета) — при следующей правке карточек свести к `.st`.

## Панель создания (`.create-panel`)

- Первым в строке параметров — проект: «В проект:» / «Собрать в:» (`select.cp-sel`).
- Любой выбор из списка (модель, формат, качество, длительность, цель, подложка…) — **только** `<label class="cp-target">Подпись: <select class="cp-sel">` → белая выпадашка-пилюля. Циклеры «клик — следующее значение» (`.cp-cycle`) не используем: не видно вариантов. Мультивыбор (форматы) — пилюли `.fmt-tg` (моно, `.on` синий), минимум один включён.
- Если выбор влияет на цену — цена на кнопке пересчитывается сразу (напр. «Кадров: 8» → «… за 8 шт.»).
- Выбор медиа из другого раздела (первый кадр ролика) — `.cp-frame`: круглая миниатюра + подпись, открывает модалку-пикер с сеткой `.fp-grid` только **принятых** кадров проекта и вариантом «Без опоры».
- Пояснение про сроки/доплаты — `.cp-note` под кнопками, одна строка.
- Долгие операции (рендер видео) — **не модалкой**: карточка сразу встаёт в сетку со статусом `.st.proc` и прогрессом `.vrender`, по готовности — toast и статус «Ждёт решения».

## Форматы и превью

- Превью формата — всегда **в настоящих пропорциях** (`.fstage` + `.bn` с `--w/--h`, размеры текста в `cq`-единицах). Никаких одинаковых прямоугольников «для примера».
- Раскладка по пропорции: `box` (обычные), `tall` (<0.8, текст внизу, кнопка на всю ширину), `strip` (>3, всё в строку).
- **Фон баннера — не заливка брендом по умолчанию.** Три варианта (`x.bg`): `''` — светлый фон бренда (surface + мягкое пятно основного цвета в углу, тёмный текст, кнопка в основном цвете) — по умолчанию; `'#brand'` — насыщенный градиент бренда, только по выбору; кадр проекта — с нейтральным тёмным затемнением под текстом (не цветом бренда), бренд — в кнопке. Иначе яркий фирменный цвет клиента спорит с синим интерфейсом и 10 форматов превращаются в стену одного цвета.
- Реклама всегда с маркировкой «Реклама · рекламодатель · erid» в каждом размере; без erid отправка блокируется подсказкой у поля.
- Видео: карточка `.vcard` (постер-кадр, ▶, длительность `.vdur`), наезд камеры на hover; плеер — `.modalcard.lb` + `.vstage` с переключателем форматов `.vfmt`.

## Вложения, пропуски, «план → результат»

- Приложить файл — только `.cp-attach` (пилюля со скрепкой, скрытый `input[type=file]`); выбранные файлы — чипы `.att` (иконка/превью, имя с многоточием, размер, ✕) в `.att-list` над панелью. В сообщении/результате — упоминание файла, на который опирались.
- **Плашка-пропуск везде одна** (`.phx` кликабельная, `.mk-ph` в макетах площадок): шрифт и размер — как у текста вокруг (`font-size:inherit`, Onest 600), оранжевый пунктир `rgba(154,90,34,.6)`, фон `--warn-bg`, радиус 6px, паддинг `0 6px`. В режиме ввода — поле той же ширины и высоты, строка не прыгает. В полях ввода неизвестное — не текст «[…]», а пустое поле с подсказкой и той же пунктирной рамкой (`.str-in.ph`, `.pl-facts input.ph`). Название клиента с кавычками не берём в ещё одни «» (`qn()`).
- Чего мы не знаем — **никогда не выдумываем**: в тексте плашка `[ваша скидка]`. В интерфейсе — `.phx` (оранжевая пунктирная, по клику — поле ввода, после ввода зелёная `.done`); на слайдах/баннерах — `.sl-ph` (пунктир в цвет текста). График без данных — `[данные не подключены]`.
- Дорогое действие делаем в два шага: сначала дешёвый план/набросок, который можно править (план колоды, раскадровка), потом сборка. Цена обоих шагов — на кнопках.
- Из чата ничего не публикуется: действия под ответом («Сделать баннеры», «Собрать страницу», «Снять кадр») создают **черновик** в своём разделе и дают ссылку «Открыть в …». Кадр показывается в чате карточкой со статусом.
- Контекст, на который опирается нейросеть, всегда виден и переключается (`.fmt-tg` — мультивыбор); в ответе строка «Опираюсь на: …» или «Контекст выключен — отвечаю в общем».
- Списки «мастер → деталь» (чаты) на ≤900px: сначала список, по выбору — деталь с кнопкой «‹ Все …».

## Масштабируемые превью (слайды, баннеры)

- Превью, которое должно выглядеть одинаково в миниатюре и крупно, — контейнер с `container-type:size` и размерами текста в `cqw/cqh`. **Отступы в cq-единицах ставим на внутренний слой** (`.sl > .sl-in`), а не на сам контейнер: cq-единицы на самом контейнере считаются от его родителя — текст сжимается, отступы раздуваются.

## Дизайн-код, шаблоны, группы — единые источники

- **Дизайн-код** проекта живёт только в `DESIGN[проект]` (цвета по ролям, шрифты, скругление, плотность, тон, «так говорим / так не говорим», манера фото, эталоны, логотип, история версий). `PAL` выводится из него (`syncPal()`); баннеры, слайды, кадры, карточка проекта, превью шаблонов читают только его. Цвет или шрифт руками в компоненте — запрещено.
- Правка дизайн-кода — через черновик и живое превью; сохранение показывает, **что перекрасится** (опубликованные страницы, баннеры на площадках → повторная модерация) и создаёт новую версию. Откат — тоже новая версия.
- Читаемость проверяем сами (WCAG: 4,5:1 для текста, 3:1 для крупного) и предлагаем «Подобрать», а не просто предупреждаем.
- Фирменный шрифт без веб-версии или без кириллицы — честная плашка «показываем заменой …».
- **Шаблоны** — один список `TPLS`: галерея, чипы «С чего начать» во всех панелях создания и «Использовать» берут его. Превью шаблона — всегда в дизайн-коде выбранного проекта. У своих шаблонов — цифры из Результата, у системных цифр не выдумываем.
- Набор (`kit`) создаёт всё **черновиками** и связывает: кампания ссылается на созданные лендинг и баннеры.
- **Группы покупателей** — один список `GROUPS` на проект; кампании и варианты страниц ссылаются на него по названию/метке. Карточка группы — рабочие поля, не «персона» с выдуманным именем; чего не знаем — плашкой.

## Цифры и деньги

- **Один источник данных.** Кампании, Результат, отчёты-презентации, Главная и Счёт считаются из одной модели (`CAMPS` → `DAYS` → `agg()`; журнал `JOURNAL`). Нигде не вписывать цифры руками — иначе страницы начнут противоречить друг другу.
- У каждой цифры видно происхождение: «внесено вручную», «по CRM до 28 сен», «по журналу». Пропуск в данных — серым и подписью («не внесено», «не видим — коллтрекинг не подключён»), а не нулём.
- Сравнение с прошлым периодом показываем, только если оно честное: если текущий период досчитан не полностью (нет сверки CRM), пишем «сравним после сверки», а не «▼ 50% · хуже». Изменение — стрелка + процент + «лучше/хуже», не только цвет.
- Каналы сравниваем внутри одного проекта, а не по всем клиентам сразу.
- Сигналы (не внесены данные, бюджет кончится раньше срока, цена заявки выросла) — одной функцией, и они же попадают в «Требует внимания» на Главной. Каждый сигнал — с действием.
- Платное действие проходит через `spendGate(цена, название, fn)`: не хватает денег — окно «не хватает X ₽, пополнить и продолжить»; дороже лимита подтверждения — окно подтверждения. После выполнения — запись в журнал через `charge()`.

## Графики

- Никогда две шкалы на одном графике. Две величины (расход и заявки) — два графика рядом с общей осью времени.
- Столбики: один цвет `--blue`, скругление 4px сверху, подпись только у последнего значения + «макс.» в углу; у каждого столбика подсказка по наведению и фокусу (`data-tip` → `.ctip`).
- До 31 дня — по дням, дальше — по неделям; заголовок графика говорит, что именно.
- Воронку не рисуем столбиками разной ширины (масштабы различаются в тысячи раз) — цепочка карточек с конверсией между шагами.

## Сетки на узком экране

- Колонка сетки на мобильном — `minmax(0,1fr)`, не `1fr`: иначе длинное содержимое в одну строку (ссылка, моно-текст) растягивает колонку шире экрана. У `.panel` — `min-width:0`. Проверка на 360: `document.documentElement.scrollWidth === innerWidth` на **каждом** экране, включая карточки-детали.

## Кнопки

- `.pbtn` — главное действие (одна синяя на блок). `.pbtn.ghost` — вторичные. `.showbtn` — только «Показ».
- `.mini` — действия внутри карточек/строк; `.mini.pri` — одно главное действие карточки («Принять», «Переснять бесплатно», «Подключить домен»).
- Цена действия пишется на кнопке: «Создать · до 2,25 ₽», «Переснять · 7,38 ₽», бесплатное — словом «бесплатно».
- Кнопки внутри кликабельной карточки/строки — `event.stopPropagation()`.

## Карточки и медиа

- Фото в карточке — **врезка**: 8px отступа от краёв карточки, свой радиус 8–9px (`.pcard .cover` через `background-clip:content-box`, `.mcard .mimg .ph` через `inset:8px`). На всех ширинах и во всех разделах одинаково.
- Карточка кликабельна целиком (`role="button"`, `tabindex="0"`, Enter), открывает деталь/лайтбокс.
- **Панели в одном ряду — одной высоты** (`.grid2`, `.grid3`, `.str-grid`, `.pf-grid` — `align-items:stretch`, не `start`): разная высота соседних карточек читается как недоделка. Исключение — раскладка «превью + редактор» (`.soc-grid2`, `.st-wrap`), где колонки не карточки-соседи.
- **Карточки в одной сетке — одинаковые.** Каркас: медиа сверху (врезка 8px) → название → мета-строка → нижняя строка состояния. Нижняя строка есть **у каждой** карточки, а не только у «особенной» (напр. в презентациях: «Клиент смотрел 4 мин» / «Ссылку ещё не отправляли» / «Поправьте план…»), прижата к низу (`margin-top:auto`).
- Если карточка — `<button>`, обязательно `display:flex;flex-direction:column;justify-content:flex-start`: иначе кнопка центрирует содержимое по вертикали, и в растянутом ряду у коротких карточек появляются пустые поля сверху и снизу. Проверка: у всех карточек ряда одинаковые высота и отступ медиа от верха (`getBoundingClientRect`).
- Последняя ячейка сетки может быть пунктирной «добавить ещё» (`.newcard`, `.mcard.addshot`) — с ценой мелким текстом.
- Только настоящие изображения (`img/`, `img/shots/`), никаких градиентов-заглушек вместо фото.
- Любая пара «заголовок + подпись» внутри flex-строки — обёртка с `display:flex;flex-direction:column` (баг «текст слипся в одну строку» ловили трижды).

## Таблицы

- `.tbl`: заголовки моно 10.5px капсом, строки кликабельны, hover `--inset`.
- Первая колонка: миниатюра `.pgthumb` 56×40 + название `.nm` + серая подпись/разворот.
- Пустое значение — прочерк `—` (класс `.dash`), не «нет данных».
- Раскрывающиеся подстроки — `.grp-row` на фоне `--inset`, переключатель со стрелкой, поворот 90°.
